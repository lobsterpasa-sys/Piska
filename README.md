# Hub: один аккаунт и три приложения

| Приложение | Аналог | Что делает |
|---|---|---|
| 🎧 **Voice** | Parallel | Голосовой чат для игроков: комнаты, звук напрямую между участниками (WebRTC), громкость каждого друга отдельно (чтобы слышать и игру, и друзей), эффекты голоса, текстовый чат, приглашения по ссылке |
| 🍿 **Watch** | Rave | Совместный просмотр YouTube и видео по прямой ссылке: play, пауза и перемотка синхронизируются у всех, есть очередь видео, чат и режим «управляет только ведущий» |
| ⚡ **Boost** | GearUP | Ускоритель игр: каталог игр, замер пинга, джиттера и потерь до узлов сети, автовыбор лучшего узла, живой график пинга. Есть **UDP-ретранслятор**, через который идёт игровой трафик |

**Единый аккаунт.** Пользователь регистрируется один раз (в любом приложении) и сразу входит во все три. На странице аккаунта видно, какие приложения уже подключены.

**Друзья общие для всех приложений.** Добавление по нику, заявки, статус «в сети» и «где сейчас» (например, «Voice: squad»), приглашения в комнату одной кнопкой. Приглашённый друг заходит даже в приватную комнату без пароля. Уведомления приходят в любом из трёх приложений.

**Ещё:**
- голосовой чат прямо в комнате Watch, как в Rave;
- режим рации в Voice (говорить, пока зажат пробел или кнопка);
- вход по ссылке-приглашению;
- смена пароля (остальные устройства выходят из аккаунта);
- удаление аккаунта (обязательно для App Store и Google Play).
**Одна подписка Premium** работает во всех трёх приложениях.

## Запуск

Нужен Node.js 22.13 или новее.

```bash
npm install
npm start            # http://localhost:3000
```

- `/`: аккаунт, подписка, ссылки на приложения
- `/voice`, `/watch`, `/boost`: приложения

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `PORT` | порт сервера (по умолчанию 3000) |
| `HUB_SECRET` | **обязательно в продакшене**: ключ подписи токенов. Без него после перезапуска все выходят из аккаунтов |
| `DB_FILE` | файл базы SQLite (по умолчанию `data/hub.db`) |
| `PAYMENTS_MODE` | `test`: Premium активируется без оплаты (по умолчанию). Любое другое значение отключает тестовую активацию |
| `BOOST_NODES` | JSON-список узлов ускорителя (см. ниже) |
| `RELAY_PORT` | UDP-порт встроенного узла (по умолчанию 40000) |
| `TRUST_PROXY` | `1`, если сервер стоит за nginx или Cloudflare |
| `ICE_SERVERS` | JSON-список STUN/TURN-серверов для голосового чата, например `[{"urls":"turn:turn.example.com:3478","username":"u","credential":"p"}]` |

## Тестирование

```bash
npm test             # 40 автотестов: аккаунт, друзья, подписки, комнаты, синхронизация, ретранслятор
npm run test:e2e     # 10 тестов в настоящем браузере Chromium
```

Браузерные тесты проверяют:
- регистрация один раз даёт вход во все три приложения, Premium сразу виден везде;
- два игрока в Voice соединяются по WebRTC, **звук реально идёт** (проверяются входящие аудиопакеты), работают чат и отключение микрофона;
- в Watch синхронизируются участники, очередь, чат и настройки ведущего;
- в Boost работают замер пинга, автовыбор узла, запуск сессии и мониторинг;
- друзья: заявка, уведомление в реальном времени, статус «где сейчас», приглашение в комнату, вход по нему с работающим голосом;
- режим рации в Voice и голосовой чат в комнате Watch;
- смена пароля и удаление аккаунта;
- на телефоне (375 px) нет горизонтальной прокрутки.

Тесты запускаются автоматически на GitHub при каждом пуше (`.github/workflows/test.yml`).

### Boost: как работает ускорение

1. Приложение меряет пинг, джиттер и потери до каждого узла и выбирает лучший.
2. Сервер выдаёт **подписанный токен сессии** с адресом игрового сервера.
3. Клиент шлёт на узел `HELLO <токен>`, и узел пересылает пакеты игры на игровой сервер и ответы обратно.
4. Узел не пускает трафик во внутренние сети (защита от использования как открытого прокси).

Запуск узла в другом городе (на VPS):
```bash
RELAY_SECRET=<тот же, что HUB_SECRET> RELAY_PORT=40000 npm run relay
```
и добавить его на основной сервер:
```bash
BOOST_NODES='[{"id":"fra","name":"Франкфурт","region":"eu","host":"fra.example.com","udpPort":40000,"probeUrl":"https://fra.example.com/api/boost/probe"},
              {"id":"msk","name":"Москва Pro","region":"ru","host":"msk.example.com","udpPort":40000,"premium":true}]'
```

## Что важно знать (честно)

- **Boost в браузере** только подбирает узел и следит за качеством связи. Перехватить трафик игры может только нативное приложение: `VpnService` на Android, `NetworkExtension` на iOS, драйвер TUN или WinDivert на ПК. Серверная часть (ретранслятор и сессии) для него уже готова.
- **Реальное снижение пинга** зависит от узлов: нужны VPS в городах рядом с игроками и игровыми серверами, а также списки IP-адресов серверов для каждой игры.
- **Voice через разные сети.** Для пользователей за строгим NAT (мобильный интернет) нужен TURN-сервер (coturn), его адрес задаётся в `ICE_SERVERS`. По умолчанию указан только публичный STUN.
- **Watch и Netflix/Disney+/Prime.** Rave работает с ними по партнёрским договорам. Без договоров доступны YouTube (официальный плеер) и прямые ссылки на видео.
- **Эффекты голоса** сейчас сделаны фильтрами. Настоящее изменение высоты голоса делается через AudioWorklet.
- **Оплата** в тестовом режиме. Для релиза нужны Google Play Billing и App Store (обязательны для мобильных подписок), Stripe или ЮKassa для веба, а подписка должна активироваться из вебхука платёжной системы.

## План развития

1. **Мобильные приложения.** Обернуть веб-версии в Capacitor (Android и iOS), общий вход между приложениями через Hub SSO.
2. **Нативный клиент Boost**: Android `VpnService` и ПК (Windows), подключение к ретранслятору.
3. Поднять TURN-сервер для Voice, сделать настоящий pitch-shift и шумоподавление (RNNoise).
4. Реальная оплата и вебхуки, восстановление пароля по email, вход через Google или Apple.
5. Push-уведомления о приглашениях. Переход на PostgreSQL и Redis для нескольких серверов.
