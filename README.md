# Hub: Voice, Watch и Boost в одном приложении

| Приложение | Аналог | Что делает |
|---|---|---|
| 🎧 **Voice** | Parallel | Голосовой чат для игроков: комнаты, звук напрямую между участниками (WebRTC), громкость каждого друга отдельно (чтобы слышать и игру, и друзей), эффекты голоса, текстовый чат, приглашения по ссылке |
| 🍿 **Watch** | Rave | Совместный просмотр YouTube и видео по прямой ссылке: play, пауза и перемотка синхронизируются у всех, есть очередь видео, чат и режим «управляет только ведущий» |
| ⚡ **Boost** | GearUP | Ускоритель игр: каталог игр, замер пинга, джиттера и потерь до узлов сети, автовыбор лучшего узла, живой график пинга. Есть **UDP-ретранслятор**, через который идёт игровой трафик |

**Одно приложение Hub** с нижним меню 🏠 Hub / 🎧 Voice / 🍿 Watch / ⚡ Boost. Один аккаунт и одна подписка на всё.

**Друзья общие для всех приложений.** Добавление по нику, заявки, статус «в сети» и «где сейчас» (например, «Voice: squad»), приглашения в комнату одной кнопкой. Приглашённый друг заходит даже в приватную комнату без пароля. Уведомления приходят в любом из трёх приложений.

**Ещё:**
- голосовой чат прямо в комнате Watch, как в Rave;
- режим рации в Voice (говорить, пока зажат пробел или кнопка);
- вход по ссылке-приглашению;
- смена пароля (остальные устройства выходят из аккаунта);
- удаление аккаунта (обязательно для App Store и Google Play).

## Запуск

Нужен Node.js 22.13 или новее.

```bash
npm install
npm start            # http://localhost:3000
```

- `/`: аккаунт, подписка, ссылки на приложения
- `/voice`, `/watch`, `/boost`: приложения

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `PORT` | порт сервера (по умолчанию 3000) |
| `HUB_SECRET` | **обязательно в продакшене**: ключ подписи токенов. Без него после перезапуска все выходят из аккаунтов |
| `DB_FILE` | файл базы SQLite (по умолчанию `data/hub.db`) |
| `PAYMENTS_MODE` | `test`: Premium активируется без оплаты (по умолчанию). Любое другое значение отключает тестовую активацию |
| `BOOST_NODES` | JSON-список узлов ускорителя (см. ниже) |
| `RELAY_PORT` | UDP-порт встроенного узла (по умолчанию 40000) |
| `TRUST_PROXY` | `1`, если сервер стоит за nginx или Cloudflare |
| `CORS_ORIGINS` | дополнительные адреса, с которых разрешены запросы к API (через запятую). Мобильные приложения разрешены всегда |
| `HY2_PORT`, `HY2_SNI`, `HY2_PIN`, `HY2_HOST` | Hysteria 2 на встроенном узле (для разработки; у отдельных узлов — поле `hy2` в `BOOST_NODES`) |
| `ICE_SERVERS` | JSON-список STUN/TURN-серверов для голосового чата, например `[{"urls":"turn:turn.example.com:3478","username":"u","credential":"p"}]` |

## iPhone: веб-приложение на экране «Домой»

Без Mac и без аккаунта Apple: сайт Hub устанавливается на iPhone как приложение (Safari → «Поделиться» → «На экран „Домой“»). Сайт сам подсказывает, как это сделать.
- **Одна иконка Hub**, нижнее меню, учтены вырез и полоса внизу экрана iPhone.
- **Без интернета** открывается интерфейс (service worker) или страница «Нет подключения».
- На Android и ПК в Chrome на главной есть кнопка «📲 Установить».
- Для установки сервер должен работать по **https**.

Boost на iPhone работает через приложение с поддержкой **Hysteria 2** (см. ниже). Своё VPN-приложение в App Store по правилам Apple может выпустить только компания.

## Android: приложение Hub

```bash
npm run mobile -- --api=https://ваш-сервер         # подготовить Android-проект mobile/hub/android
npm run mobile -- --api=https://ваш-сервер --apk   # + собрать APK в mobile/dist/hub-debug.apk (нужен Android SDK, ANDROID_HOME)
```

Без `--api` приложение ходит на `http://10.0.2.2:3000`: так эмулятор Android видит сервер на вашем компьютере. На телефоне адрес сервера меняется на экране входа (⚙ Сервер). Проект открывается в Android Studio. Ссылки `hubapp://room?app=voice&name=…` открывают комнату в приложении.

## Hysteria 2: Boost для iPhone и других устройств

Узел может работать как сервер **Hysteria 2** (QUIC, TLS 1.3, при желании маскировка salamander). В Boost человек нажимает «Получить ключ и QR-код» и сканирует его в приложении с поддержкой Hysteria 2 (sing-box, Streisand, Shadowrocket и др.).
- **Кого пускать, решает Hub** (`POST /api/boost/hy2/auth`). Ключ личный, действует 30 дней. Смена пароля или удаление аккаунта отзывает его сразу, Premium-узлы пускают только Premium.
- **Узел не пускает во внутренние сети** и на почтовый порт 25 (ACL в комплекте).
- Проверено с настоящим Hysteria 2 v2.13.0: UDP и TCP через узел, поддельный и отозванный ключ не проходят, ACL работает (`HYSTERIA_BIN=… npm test`).

Комплект для узла: `deploy/hysteria/`:
```bash
HUB_URL=https://hub.example.com NODE_NAME=fra.hub.example.com HUB_SECRET=… ./deploy/hysteria/install.sh
```
`install.sh` собирает Hysteria из исходников, делает сертификат и запускает Hysteria и UDP-ретранслятор как службы. **Скрипт ещё не запускался на настоящем сервере.** Отпечаток сертификата, который печатает `make-cert.sh`, добавьте в `BOOST_NODES`:
```json
{"id":"fra","name":"Франкфурт","region":"eu","host":"fra.hub.example.com","udpPort":40000,
 "hy2":{"port":443,"sni":"fra.hub.example.com","pinSHA256":"AA:BB:…"}}
```
С самоподписанным сертификатом в ссылку добавляется `insecure=1` вместе с `pinSHA256`. Не все приложения проверяют отпечаток, поэтому для запуска лучше настоящий сертификат: блок `acme` в `config.yaml`, тогда `pinSHA256` не нужен.

## Тестирование

```bash
npm test             # 46 автотестов: аккаунт, друзья, подписки, комнаты, ретранслятор, ключи Hysteria
npm run test:e2e     # 18 тестов в настоящем браузере Chromium
HYSTERIA_BIN=/путь/к/hysteria npm test   # + 2 теста с настоящим Hysteria 2
```

Браузерные тесты проверяют:
- регистрация один раз даёт вход во все три приложения, Premium сразу виден везде;
- два игрока в Voice соединяются по WebRTC, **звук реально идёт** (проверяются входящие аудиопакеты), работают чат и отключение микрофона;
- в Watch синхронизируются участники, очередь, чат и настройки ведущего;
- в Boost работают замер пинга, автовыбор узла, запуск сессии и мониторинг;
- друзья: заявка, уведомление в реальном времени, статус «где сейчас», приглашение в комнату, вход по нему с работающим голосом;
- режим рации в Voice и голосовой чат в комнате Watch;
- смена пароля и удаление аккаунта;
- приложение Hub для Android: страницы приложения и сервер на разных адресах, нижнее меню, ссылки `hubapp://`;
- iPhone: подсказка по установке, нижнее меню, работа без сети, QR-код Hysteria 2;
- на телефоне (375 px) нет горизонтальной прокрутки.

Тесты запускаются автоматически на GitHub при каждом пуше (`.github/workflows/test.yml`).

### Boost для Android: настоящее ускорение

В Android-приложении Hub раздел Boost включает VPN **только для выбранной игры** (`VpnService` + `addAllowedApplication`). Остальные приложения телефона идут как обычно.
- **UDP игры** (матчи, от него зависит пинг) отправляется на узел в режиме мультиплекса (`HELLO2`). Узел пересылает пакеты на игровые серверы и возвращает ответы.
- **TCP** (лобби, магазин, загрузки) перенаправляется на локальный прокси и уходит напрямую, чтобы игра не ломалась.
- **DNS** идёт напрямую.
- Экран показывает реальный пинг до узла, джиттер, потери и объём трафика игры через узел.

Код: `mobile/native/` (Java). JVM-тесты разбора и сборки пакетов запускаются при сборке APK.

### Boost: как работает ускорение

1. Приложение меряет пинг, джиттер и потери до каждого узла и выбирает лучший.
2. Сервер выдаёт **подписанный токен сессии** с адресом игрового сервера.
3. Клиент шлёт на узел `HELLO <токен>`, и узел пересылает пакеты игры на игровой сервер и ответы обратно.
4. Узел не пускает трафик во внутренние сети (защита от использования как открытого прокси).

Запуск узла в другом городе (на VPS):
```bash
RELAY_SECRET=<тот же, что HUB_SECRET> RELAY_PORT=40000 npm run relay
```
и добавить его на основной сервер:
```bash
BOOST_NODES='[{"id":"fra","name":"Франкфурт","region":"eu","host":"fra.example.com","udpPort":40000,"probeUrl":"https://fra.example.com/api/boost/probe"},
              {"id":"msk","name":"Москва Pro","region":"ru","host":"msk.example.com","udpPort":40000,"premium":true}]'
```

## Что важно знать (честно)

- **Boost в браузере** только подбирает узел и следит за качеством связи. Пустить игру через узел может Android-приложение Hub (пока **не проверено на настоящем телефоне**: здесь нет эмулятора) или приложение с Hysteria 2 по ключу из Hub. Своё VPN-приложение для iPhone требует аккаунт Apple компании. Для ПК нужен драйвер TUN или WinDivert.
- **Блокировки в России.** Наш UDP-протокол и Hysteria 2 блокировать труднее, чем WireGuard и OpenVPN, но гарантий нет: проверять нужно на реальных провайдерах. Ограничения касаются сервисов для обхода блокировок сайтов. Перед запуском проконсультируйтесь с юристом.
- **Встроенный узел** работает на том же сервере (UDP-порт `RELAY_PORT`, по умолчанию 40000). Этот порт должен быть открыт в файрволе. Внешний адрес задаётся `RELAY_PUBLIC_HOST`, если он отличается от адреса сайта.
- **Реальное снижение пинга** зависит от узлов: нужны VPS в городах рядом с игроками и игровыми серверами, а также списки IP-адресов серверов для каждой игры.
- **Voice через разные сети.** Для пользователей за строгим NAT (мобильный интернет) нужен TURN-сервер (coturn), его адрес задаётся в `ICE_SERVERS`. По умолчанию указан только публичный STUN.
- **Watch и Netflix/Disney+/Prime.** Rave работает с ними по партнёрским договорам. Без договоров доступны YouTube (официальный плеер) и прямые ссылки на видео.
- **Эффекты голоса** сейчас сделаны фильтрами. Настоящее изменение высоты голоса делается через AudioWorklet.
- **Оплата** в тестовом режиме. Для релиза нужны Google Play Billing и App Store (обязательны для мобильных подписок), Stripe или ЮKassa для веба, а подписка должна активироваться из вебхука платёжной системы.

## План развития

1. **Проверить APK и веб-версию на настоящих телефонах**, сделать подписанную сборку для Google Play.
2. **Boost**: встроить Hysteria 2 в Android-приложение (TCP тоже через узел, шифрование), клиент для ПК, списки серверов игр.
3. С компанией (ООО) и аккаунтом Apple: Hub в App Store со встроенным Boost.
4. Поднять TURN-сервер для Voice, сделать настоящий pitch-shift и шумоподавление (RNNoise).
5. Реальная оплата и вебхуки, восстановление пароля по email, вход через Google или Apple.
6. Push-уведомления о приглашениях. Переход на PostgreSQL и Redis для нескольких серверов.
